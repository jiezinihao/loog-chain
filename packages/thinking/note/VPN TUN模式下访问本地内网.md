# VPN TUN 模式下访问本地内网

> 开启 Clash/Mihomo 的 TUN 模式后，本地内网可能因路由被虚拟网卡接管而无法访问。解决重点是让目标网段直连，并将它排除在 TUN 路由之外。

## 问题现象

未开启 TUN 时，可以正常访问 `10.1.126.5`、`10.1.126.14` 等内网地址；开启后访问失败。

这是因为 TUN 的自动路由会接管系统流量，内网请求也可能被送入虚拟网卡，而不是原来的物理网卡。

## Merge 配置

在 Clash Verge 的 Merge 配置中增加以下内容：

```yaml
prepend-rules:
  # 10.1.126.x 内网流量优先直连
  - IP-CIDR,10.1.126.0/24,DIRECT,no-resolve

tun:
  # 从 TUN 自动路由中排除本地内网，交给物理网卡处理
  route-exclude-address:
    - 10.1.126.0/24
```

保存后重新启用 Merge，并重启 Clash 或 TUN。代理模式应选择“规则”，TUN 的“自动设置全局路由”保持开启，“严格路由”保持关闭。

`DIRECT` 决定 Mihomo 如何转发请求，`route-exclude-address` 则让目标网段不进入 TUN。两者同时配置，更适合本地内网访问场景。

## CIDR 范围

- `10.1.126.0/24`：匹配整个 `10.1.126.x`，适合当前场景。
- `10.1.0.0/16`：匹配整个 `10.1.x.x`，范围更大。
- `10.1.126.5/32`：只匹配一个指定 IP。

配置时应优先使用能够覆盖目标地址的最小网段，避免把 VPN 远端同样使用的内网地址错误排除。

## 排查要点

如果配置后仍然无法访问，依次确认：Merge 已启用、规则位于订阅规则之前、重启后配置已经重新生成，以及目标地址本身在未开启 TUN 时可以访问。
